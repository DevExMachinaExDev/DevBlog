So we had a bit of a day of using binary searches in a new way today but ultimately learned quite a lot from it!

NEW

## Search rotated sorted array
A good use of a classic but modified binary search tree here. The key being remembering that rotated arrays will always have a sorted and unsorted side.

## Minimum window substring
I was a little dreading this one coming back up as it was a little bloated on the actualy writing part, but i took it as an opportunity to convert the mapped version i did previously into a version using arrays as lookup tables. It went pretty well, but I maintain what i said at the time that the map version would for the most part be a better production version due to its scalability.

## Koko eating bananas
Boy I had a hard time with this one today. I guess the real lesson here was that if you are stuck for a long time you are probably thinking about it all wrong and if you still think about it wrong after a certain amount of time it might be worth looking it up. There is no shame in not being able to figure something else, you can't be expected to reinvent every single algorithm perfectly every time, but don't let the fact that these algorithms have known solutions become a crutch as your problem solving skills will become rusty.

## Capacity To Ship Packages Within D Days
More or less in the bag after Koko eating bananas, but a good practice run once I had the algorithm to see where else it could be used.

Overall today was a good example of how failure can be the best teacher. The important part being that you have to actually take the time to fail for the learning to actually stick.

## Key takeaways.
- Binary search isn't just for finding values, it's for finding answers.
- If you're stuck for too long, you're probably looking at the problem the wrong way.
- Looking up a solution is fine. Relying on it is not.
- Failure only becomes a lesson if you take time to understand it.
- Algorithms are tools. Its up to you to know which to use.
