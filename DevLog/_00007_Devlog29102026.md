## Group anagrams

I spent a lot longer on this than I probably should have done as it did not sit right with me the first time i did the solution that I was sorting the string when i knew that i could build a mapping version that builds a unique version every time. So i tried to make it....... and it was slower.... much slower. I suspect that may be because you only see the benefit on extremely large strings and this version has to do 26 string appends per anagram to build the unique has string which is probably way slower than just sorting the 3 character string and just using that. It was an interesting experiment though and we now know we can build unique hashes this way although a small bit of research showed that there are built in hash functions that i could have potentially used.

## Key takeaways

- Sometimes simple solutions with worse time complexities can outperform clever ones with better time complexities depending on things such as branching and the data set.
- If possible for the problem you can track matches instead of rescanning arrays.
- Reusing code can be beneficial to overall output. No need to reinvent the wheel.
- Spaced repetition can help patterns stick.
- Maintainability matters more than perfection.
- Be kinder to yourself on difficult days.
