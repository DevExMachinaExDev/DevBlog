# _00001_Devlog21102026

So today I solved 3 leetcode questions which were:

- group anagrams
- top k frequent elements
- valid sudoku

and a quick refresh on the two sum problem to warmup.

Most of these questions had a common theme of the tradeoff between storing information using that extra memory to prevent having to do a lot of extra unnecessary work. A good example of this would be in the group anagrams example where there was readability improvements from just sorting the strings and then using that to make comparisons and who doesn't love just getting C++ to do your sorting for you!

There was also a lot of exploration into readability vs performance. I feel there is a time and a place for both and unless there is an express reason readability can sometimes be king. Of course Leetcode doesn't really see it this way :D but in the real world this can save a lot of developer energy and costs.

We took a look at an old unused technique which was the bucket sort. One of my favourite algorithms to use when you just want pure speed but definitely very situational as that memory overhead can get silly, plus of course the silly seaside name is a lot more memorable than some of the algorithms that are just the name of some random guy!

A big takeaway here was also time management and when you should just move on. Those who look at my discussions would note that my solutions often have some unusual way of making best case scenarios faster or selective algorithms as this is likely how they would appear in a real software application (if an application had some very strange requirements!) I like to do these as thought experiments but I don't always code them for a simple reason. Sometimes you just need to keep the code coming and additional to that sometimes you have to weigh up whether you should spend time optimising a best case when it is indeed the rarest case. I guess the same may be said for trying to mitigate rare cases as well... but there you go.

Anyway another fairly successful day. No huge speedbumps so far and its been a good refresher. I might not always get the best solution, but I'm always learning.
