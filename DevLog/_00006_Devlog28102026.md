## minimum size sub array sum
Almost the inverse of longest repeating character replacement. This is really an example of how pattern recognition can really make or break a coder, I found this so much easier after the previous question and understanding it as the answer is so similar and a lot of real world problem solving is applying crystallised knowledge at the right time rather than fluid skills, but always good to keep that fluid intelligence topped up as well because they can't all be the same problems!

## Key takeaways
- Understanding why a pattern works is more valuable than memorising the pattern itself.
- Using AI for hints and not solutins can enhance learning not hinder it but it requires discipline.
- Perfectionism can blind you to the fact that you will fail, and often.
- Revisiting a question does not mean you should scan the requirements, READ THE QUESTION! (I will undoubtedly write this again down the line).
- Sliding windows do not need to always be correct.
- Bookkeeping and tracking are more important than the sliding window.
- Pattern recognition can make problem solving trivial, but should not be your only tool.
- Fluid reasoning needs to be worked on as well as pattern recognition.
